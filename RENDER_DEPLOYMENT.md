# Развертывание на Render

## 🚀 Шаги развертывания

### 1. Подготовка
- Убедитесь, что репозиторий на GitHub
- Репозиторий может быть приватным, но Render должен иметь доступ

### 2. Создание сервисов на Render

#### Вариант A: Автоматический (через render-deploy.yaml)
1. Зайдите на [Render Dashboard](https://dashboard.render.com)
2. Нажмите "New" → "Blueprint"
3. Выберите ваш GitHub репозиторий
4. Render автоматически прочитает файл `render.yaml`
5. Все сервисы создадутся автоматически

#### Вариант B: Ручной
1. Создайте PostgreSQL базу данных
2. Создайте Node.js Web Service
3. Настройте переменные окружения (см. ниже)

### 3. Переменные окружения на Render

Render автоматически передаст переменные из базы данных:
- `DB_HOST` - хост БД (заполняется автоматически)
- `DB_PORT` - порт БД (заполняется автоматически)
- `DB_NAME` - имя БД (заполняется автоматически)
- `DB_USER` - пользователь БД (заполняется автоматически)
- `DB_PASSWORD` - пароль БД (заполняется автоматически)
- `NODE_ENV` = production (автоматически)

### 4. Процесс развертывания

1. **Первое развертывание:**
   ```
   ✓ Сборка Docker образа
   ✓ Запуск приложения (port 3000)
   ✓ Подключение к БД (до 30 попыток)
   ✓ Инициализация таблиц
   ✓ Вставка тестовых данных
   ```

2. **После развертывания:**
   - Приложение сразу отвечает на `/health`
   - БД инициализируется в фоне
   - API товаров доступен на `/api/products`
   - Админ-панель на `/push`

### 5. Проверка статуса

```bash
# Проверить health status
curl https://your-app.onrender.com/health

# Получить список товаров
curl https://your-app.onrender.com/api/products

# Проверить админ-панель
https://your-app.onrender.com/push
```

## ⚠️ Важные моменты

### Таймауты
- Первый запуск может занять до 60 секунд
- БД инициализируется асинхронно
- Health check отвечает немедленно

### Масштабирование
- Render автоматически выбирает количество инстансов
- Для production используйте план "standard"
- PostgreSQL starter план достаточно для малых объемов

### Резервные копии БД
- Настройте резервные копии в панели Render
- Минимум 1 резервная копия каждый день

## 🔧 Troubleshooting

### Приложение не запускается
1. Проверьте логи на Render Dashboard
2. Убедитесь, что `package-lock.json` в репозитории
3. Проверьте соответствие Node 18 версии

### БД не подключается
1. Проверьте переменные окружения
2. Убедитесь, что БД сервис создан
3. Проверьте зависимость между сервисами

### Медленное первое развертывание
- Это нормально для первого запуска
- Дождитесь завершения инициализации БД
- Следующие развертывания будут быстрее

## 📊 Мониторинг

На Render Dashboard вы можете видеть:
- Логи развертывания и выполнения
- CPU и Memory использование
- Network трафик
- Статус сервисов

## 💼 Production рекомендации

1. **Безопасность:**
   - Используйте strong пароли для БД
   - Включите SSL/TLS
   - Ограничьте IP доступ если нужно

2. **Мониторинг:**
   - Настройте alert на ошибки
   - Мониторьте размер БД
   - Проверяйте логи ошибок

3. **Обновления:**
   - Регулярно обновляйте зависимости
   - Проверяйте security updates
   - Тестируйте обновления локально
